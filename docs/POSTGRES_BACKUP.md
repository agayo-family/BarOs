# Резервная копия PostgreSQL и проверка восстановления

Это инструмент оператора. Он не означает, что рабочая база уже скопирована или автоматическое хранение настроено. CSV-отчёт сотрудников и копия кода не заменяют резервную копию БД.

Нужны Python с зависимостями проекта и PostgreSQL client tools подходящей версии. Для текущего PostgreSQL 16 используйте `pg_dump` и `pg_restore` версии 16; каталог можно указать в `PG_BIN`. Строка подключения задаётся в окружении `DATABASE_URL`, без передачи пароля в аргументах команды или в чат.

```bash
python ops/postgres_backup.py backup /private/backups/baros-20261026
```

Каталог должен быть новым, родительский каталог — существующим. Права: каталог 0700, архив и манифест 0600. Сохраняйте вместе `baros.dump` и `manifest.json` в контролируемом внешнем хранилище с шифрованием и ограниченным доступом: архив содержит все данные платформы. Не добавляйте их в Git или публичные файлы. Файлы `.partial` означают незавершённую копию.

Архив и хеши содержимого таблиц строятся из одного экспортированного снимка. Это позволяет проверить не только число строк, но и содержимое, включая двоичные исходники, редакции и письменные ответы. Успешный `pg_dump` ещё не подтверждает восстановление.

Создайте отдельную пустую тестовую БД и задайте её подключение в `RESTORE_TEST_DATABASE_URL`. Рабочую БД здесь не используйте.

```bash
python ops/postgres_backup.py verify /private/backups/baros-20261026
```

Проверка сверяет SHA-256 архива, отказывается от непустой цели, восстанавливает одним транзакционным запуском и сравнивает число строк и хеши всех обычных пользовательских таблиц. Она не удаляет и не перезаписывает существующие таблицы. Пароль передаётся клиентским инструментам через окружение. После проверки тестовую базу обслуживает оператор по правилам выбранной инфраструктуры.

Для продаж остаётся настроить регулярный запуск, внешнее хранение, срок хранения, контроль неудачных копий и периодическую проверку восстановления. В production также проверяются роли/права и внешние файлы, если они появятся: `pg_dump` одной базы не копирует глобальные роли кластера или внешнее объектное хранилище.

Основание: [pg_dump](https://www.postgresql.org/docs/16/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/16/app-pgrestore.html), [синхронизация снимков](https://www.postgresql.org/docs/16/functions-admin.html#FUNCTIONS-SNAPSHOT-SYNCHRONIZATION).
