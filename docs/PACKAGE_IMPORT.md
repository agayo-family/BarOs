# Импорт учебных пакетов BarOS 2.6

Файл UTF-8 `.baros.json` / `.json`, максимум 2 МиБ. Управляющий открывает «Обучение → Импорт из файла» либо «Тесты из файла → Импорт из файла», проверяет предварительный просмотр и импортирует черновик. Один и тот же нормализованный пакет в одном заведении повторно не создаётся. Изменённый пакет создаёт новый материал и не меняет прошлые попытки.

Импорт не вызывает AI. Публикация выполняется отдельно после проверки содержания и назначенных должностей. Пакет содержит ключи: его передают управляющему, участники работают через свои аккаунты.

## Полный курс

`kind: "course"` использует существующий `CourseIn` из `baros/v2/schemas.py`. Нужны непустые `lessons` и `questions`; `quiz_size` не больше банка. Вопрос курса содержит ровно четыре различных варианта, `correct_index` от 0 до 3, объяснение и тип `knowledge`, `understanding`, `sales` или `scenario`.

```json
{
  "format": "baros-package",
  "version": 1,
  "kind": "course",
  "course": {
    "title": "Температура по стандарту",
    "positions": ["bartender"],
    "quiz_size": 1,
    "lessons": [{"title": "Стандарт", "body": "В этом учебном примере воду для чая нагревают до 90 °C."}],
    "questions": [{
      "prompt": "Какую температуру воды задаёт стандарт примера?",
      "choices": ["90 °C", "80 °C", "70 °C", "60 °C"],
      "correct_index": 0,
      "explanation": "В стандарте примера указаны 90 °C.",
      "type": "knowledge"
    }]
  }
}
```

После публикации теория и тест используют одну опубликованную версию. Карточки и игры берут тот же банк. Для режима «Пары» нужны хотя бы два разных ответа, для сборки из слов — ответ из 2–24 слов. Если подходящих вопросов нет, режим недоступен и интерфейс объясняет причину. Импорт не придумывает дополнительные факты или игровые задания.

## Отдельный тест

`kind: "assessment"` создаёт проверочную работу без уроков, карточек и игр. `assessment` включает `title`, `positions`, `sections`, `tasks`, `instructions`, `time_limit_minutes` (1–720), `max_attempts` (1–20), `passing_score` (проценты 0–100 либо `null` для диагностики) и `sequential_sections`.

Раздел: уникальный `id`, `title`, необязательные `instructions`. Задание: уникальный `id`, существующий `section_id`, `prompt`, положительный вес `points` и вид:

- `single_choice`: 2–8 различных `choices`, `correct_index` с нуля, необязательное `explanation`;
- `written`: непустой `rubric`, ограничение `max_length` (100–30000 символов). Каждый критерий содержит уникальный `id`, `label`, положительные `points` и `guidance` для проверяющего.

Письменная оценка = вес задания × сумма первичных оценок / сумма максимумов критериев. Например, четыре критерия по 1 баллу при весе задания 0,75 дадут максимум 0,75. Сумма весов может быть произвольной; результат содержит баллы, максимум и процент.

Необязательное `score_cap` письменного задания задаёт `{ "points": 12, "guidance": "Когда применяется предел и как его обосновать." }`. Предел ниже максимума задания. Проверяющий отмечает применение предела и обязательно пишет причину; сервер берёт минимум из взвешенной оценки и предела. Первичные оценки сохраняются. Применение правила по смыслу ответа определяет человек.

Тест открывается назначенным должностям после публикации. Разделы при последовательном режиме открываются по одному; сданные ответы менять нельзя. Таймер общий и не останавливается при закрытии вкладки. Варианты выбора перемешиваются на сервере. Снимок задания сохраняется в попытке.

Ответы сохраняются автоматически и кнопкой. Очередь сохраняет новый текст после завершения предыдущего запроса; сдача ждёт всей очереди. При ошибке текст сохраняется в текущей вкладке и сообщение просит повторить сохранение. Закрытие вкладки до успешного сохранения не гарантирует восстановление текста на другом устройстве. При конфликте версии необходимо обновить попытку.

Ключи, объяснения и рубрики сотруднику не передаются. Работа с письменными заданиями ждёт ручной оценки всех критериев. До завершения проверки сотрудник не получает промежуточный итог. Чистый тест с вариантами проверяется автоматически. Отдельная диагностика не создаёт фиктивный прогресс обычного курса или XP.

## Редактирование отдельного теста

Откройте «Тесты из файла» → нужный тест → «Редактировать тест». Раскройте раздел и задание, чтобы изменить содержание. Кнопка «Удалить раздел» удаляет и его задания; до сохранения правку можно отменить. Доступны копирование, перестановка, перенос задания в другой раздел, смена типа ответа и изменение критериев. «Отменить действие» и «Повторить действие» работают и для ввода текста. После проверки нажмите «Сохранить изменения»; для опубликованного теста отметьте подтверждение внизу формы.

Несохранённые правки сохраняются в текущей вкладке и предлагаются к восстановлению после перезагрузки. Их можно отдельно скачать кнопкой «Скачать текущий файл». Файл содержит правильные ответы и рубрики, поэтому предназначен только управляющим. При ошибке связи повторите сохранение; при конфликте другой вкладки скачайте свои правки перед загрузкой сохранённой версии. После изменения должностей новые участники увидят тест сразу после сохранения; уведомления отправляются отдельной кнопкой «Проверить и опубликовать» на странице теста.

Управляющий с правом `courses_manage` может изменить существующий импортированный тест: название, описание, инструкции, должности, таймер, лимит попыток, порог, порядок разделов, задания, варианты и ключи, рубрики и ограничения балла. Разделы и задания можно добавлять, удалять и переставлять; сохраняется целый проверенный `AssessmentIn`, а не частичный patch. Каждый оставшийся раздел должен содержать хотя бы одно задание. Размер сохранённого UTF-8 JSON ограничен 2 МиБ.

Просмотр теста управляющим возвращает `package` и `revision` — SHA256 точной сохранённой строки payload. Для сохранения используется `PUT /api/assessments/{id}` с `{ "revision": "<64 hex>", "assessment": <AssessmentIn>, "reviewed": false }`. Ответ: `{ "ok": true, "id": <id>, "revision": "<новый SHA256>" }`. Если содержимое изменили после открытия редактора, сервер возвращает 409; нужно загрузить актуальную версию и сверить правки. Некорректное содержимое не записывается.

Для уже опубликованного теста обязательно явное `reviewed: true`: сохранённые изменения сразу действуют для новых попыток. Флаги публикации и архива при сохранении не меняются. Существующие начатые, сданные и проверенные попытки сохраняют свои формулировки, ключи, рубрики, баллы, таймер и настройки в прежнем snapshot. После смены назначения прежние попытки проверяют должности по своему snapshot; новые попытки используют актуальные должности. Если новое назначение сотруднику не подходит, но у него есть доступная прежняя попытка, список и страница показывают её старое название, описание и инструкции с `can_start: false`, а не новое содержание. Начатую работу можно продолжить, сданную — открыть, но начать новую нельзя. Архивирование по-прежнему закрывает доступ. Само сохранение правок не отправляет новые уведомления.

Сохранение, публикация, архивирование и получение snapshot при новом старте сериализуются блокировкой строки теста. Редактирование не изменяет исходный файл и не создаёт новую запись теста; повторный импорт файла остаётся отдельной операцией.

## API и данные

- `POST /api/packages/preview`, `POST /api/packages/import` с `{ "package": <пакет> }` доступны управляющему с `courses_manage`;
- `/api/assessments` — список, просмотр, публикация с `{ "reviewed": true }`, архивирование и старт;
- `GET /api/assessments/{id}` возвращает управляющему `package` и `revision`; `PUT` сохраняет полный `assessment` с проверкой `revision` и подтверждением опубликованных изменений;
- `/api/assessment-attempts/{id}` — просмотр и сохранение с `version`; `/advance`, `/submit`, `/review`;
- `/review` принимает `grades` по критериям, `feedback` и необязательный `applied_caps: { "task_id": true }`.

Изоляция по заведению, должностям, аккаунту, CSRF и текущей подписке действует и для импорта. Запуск обычного и письменного экзамена использует общий Account lock; проверка конкурирующей попытки идёт после блокировки. Автосдача по таймеру не освобождает блокировку попытки до конца операции.

Новые таблицы `v2_imported_assessments`, `v2_package_receipts`, `v2_written_attempts` создаются существующим `Base.metadata.create_all` при запуске. Перед публикацией отдельно проверить резервную копию и создание таблиц на целевой PostgreSQL. Локальные проверки используют временную SQLite и не подтверждают гонки реального PostgreSQL нагрузочным тестом.
