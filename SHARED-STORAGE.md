# Общая база Tincture Lab: запуск и перенос

Подготовленная версия ещё не опубликована. Пользователь выбрал Neon Free. Настоящее подключение PostgreSQL и облачная настройка пока не проверены. Публикация исходников в открытый GitHub требует отдельного разрешения пользователя.

## Локальный запуск

Нужны Node.js 24.19.0+ и pnpm 11.25.0. Из корня проекта:

```powershell
npm install --global --ignore-scripts pnpm@11.25.0
pnpm install --frozen-lockfile --ignore-scripts
$env:SQLITE_PATH = './work/local.sqlite'
$env:FIRST_RUN_TOKEN = node --input-type=module -e "import { randomBytes } from 'node:crypto'; process.stdout.write(randomBytes(32).toString('base64url'))"
$env:FIRST_RUN_TOKEN
pnpm start
```

Откройте `http://localhost:3000`. На первом экране введите созданный код и задайте два разных пароля минимум по 12 символов: владельца и сотрудников. Код первоначальной настройки и пароли не записываются в репозиторий или отчёт. После настройки `FIRST_RUN_TOKEN` можно убрать из окружения: повторная настройка закрыта записью в базе.

SQLite разрешена только для локальной работы и тестов. Для локального PostgreSQL вместо `SQLITE_PATH` задайте `DATABASE_URL`; одновременно эти переменные запрещены. Проверки: `pnpm test` либо `node --test tests/*.test.mjs`. В ограниченной среде тестам нужен доступ к локальному адресу `127.0.0.1`.

## Публикация

`Dockerfile.shared` устанавливает pnpm 11.25.0 и зависимости по неизменяемому `pnpm-lock.yaml`, затем запускает Node-сервер. Сервер обслуживает интерфейс и API. Публикация только статической папки не запускает общую базу.

`render-shared.yaml` подготовлен для бесплатного веб-сервиса Render в регионе Frankfurt и внешней базы Neon Free. Платную базу Render конфигурация не создаёт. `DATABASE_URL` вводится как секрет при настройке сервиса. Контейнерное файловое хранилище не заменяет PostgreSQL.

В Neon создайте отдельный проект `tincture-lab-shared` в регионе AWS Europe Central 1 (Frankfurt), с PostgreSQL 18 и базой `tincture_lab`. Используйте только PostgreSQL; дополнительные сервисы для текущего приложения не нужны. Скопируйте PostgreSQL connection string из окна Connect, сохранив параметры защищённого TLS, и задайте его в Render как `DATABASE_URL`. Строка подключения не должна попадать в GitHub, архив исходников, отчёты или резервные копии рабочей базы.

По проверенному 14 октября 2026 года тарифу Neon Free включает 1 ГБ хранения и 100 CU-часов в месяц на проект, без срока пробного периода. Бесплатность зависит от объёма данных и нагрузки; фотографии входят в объём базы. База засыпает после периода бездействия, поэтому первый запрос может занять больше времени. Веб-сервис Render также может просыпаться с задержкой.

Чтобы экономить квоту, скрытые вкладки не проверяют изменения. Видимая вкладка проверяет их раз в минуту, а при возвращении проверка происходит сразу. Render использует `/api/live`, который не обращается к базе. `/api/health` предназначен для ручной проверки готовности с настоящим запросом PostgreSQL, а не для постоянного мониторинга. Проверка версии читает только номер версии, без загрузки всей рабочей базы.

Переменные среды:

| Переменная | Назначение |
| --- | --- |
| `NODE_ENV=production` | Запрещает SQLite и включает защищённую cookie. |
| `DATABASE_URL` | Секрет подключения к Neon PostgreSQL с TLS. |
| `FIRST_RUN_TOKEN` | Случайный секрет единственной первоначальной настройки. Blueprint может сгенерировать его; пользователь получает его из кабинета или задаёт собственный случайный секрет. |
| `PUBLIC_ORIGIN` | Основной HTTPS-адрес без пути. Для стандартного адреса Render используется `RENDER_EXTERNAL_URL`; для своего домена задайте `PUBLIC_ORIGIN`. |
| `PORT` | По умолчанию локально 3000, в Docker 10000. |
| `MAX_BODY_BYTES` | Необязательно: по умолчанию 104857600 байт, то есть 100 МиБ. |
| `SESSION_TTL_MS` | Необязательно: по умолчанию 604800000 мс, то есть семь дней. |

Production не запускается без PostgreSQL или допустимого HTTPS-origin. Проверка `/api/health` включает доступность базы. Секреты задаются через кабинет провайдера, а не через исходники. Пользователь получает первоначальный код, вводит выбранные пароли в форму первого запуска и передаёт сотрудникам только их пароль и адрес сайта подходящим способом. Владелец хранит свой пароль и первоначальный код отдельно.

После настройки проверьте обе роли, одинаковую базу на втором устройстве, конфликт одновременных правок, сохранность после перезапуска и полную выгрузку JSON. Настройте резервное копирование PostgreSQL у провайдера и регулярно сохраняйте отдельные полные копии. Локальные SQLite-тесты не подтверждают облачную публикацию или настоящий PostgreSQL.

## Перенос прежней базы

IndexedDB привязана к протоколу, домену и порту. Новый адрес не может прочитать базу старого адреса даже в том же браузере. При прежнем origin владелец увидит предложение перенести всю прежнюю IndexedDB; она открывается только для чтения и не удаляется.

При новом адресе:

1. На устройстве с рабочими данными откройте прежний сайт под прежним адресом.
2. В настройках скачайте **полную резервную копию JSON**. Выгрузка только технологических карт не включает склад, заявки, планы, партии и историю.
3. На новом сайте владелец выполняет первоначальную настройку и загружает полную копию JSON.
4. Проверьте карты, архив, фотографии, заявки, склад, планы, партии, стоп-лист, статистику и просмотренные уведомления. Откройте ту же базу на втором устройстве.
5. Сохраните старую копию и прежнюю IndexedDB до проверки переноса. Затем скачайте полную копию с нового сервера.

Первую общую базу создаёт только владелец. Последующее восстановление копии через настройки заменяет общую базу для всех устройств; интерфейс требует подтверждение и предлагает предварительно скачать текущие данные. Прикреплённые фотографии входят в JSON; внешние HTTPS-фотографии остаются ссылками и зависят от исходного сайта.

## API

API не кэшируется (`Cache-Control: no-store`). Ошибки: `{error,code}` с соответствующим HTTP-статусом. Все изменяющие запросы требуют совпадающего Origin и JSON; после входа также нужен `X-CSRF-Token`. Случайная cookie `HttpOnly`, `SameSite=Strict`, `Secure` в production; сессия хранится в базе в виде хеша токена.

| Метод и путь | Тело / результат |
| --- | --- |
| `GET /api/live` | Без входа; проверка работающего сервера без обращения к базе. |
| `GET /api/health` | Без входа; `{ok:true}` после проверки базы. |
| `GET /api/session` | `{authenticated,role,csrfToken,initialized}`; без входа роль и CSRF равны `null`. |
| `POST /api/setup` | `{token,ownerPassword,staffPassword}`; атомарно один раз, возвращает сессию владельца. |
| `POST /api/login` | `{password,role}`; роль `owner` или `staff`, возвращает сессию. |
| `POST /api/logout` | `{}` и CSRF; отзывает текущую сессию и очищает cookie. |
| `POST /api/password` | `{currentPassword,ownerPassword?,staffPassword?}`; только владелец, хотя бы один новый пароль. Возвращает сессию; сессии изменённой роли отзываются. При смене пароля владельца cookie и CSRF обновляются. |
| `GET /api/state` | После входа; `{state,revision}`. `state:null` до первого переноса. |
| `GET /api/revision` | После входа; `{revision}`. |
| `PUT /api/state` | `{state,revision,mutationId}` и CSRF; первая запись только владельцем. Ответ `{revision}`. |

`mutationId` — UUID. Данные и подтверждение записываются одной транзакцией. Повтор того же идентификатора, состояния и исходного номера версии возвращает первоначальный результат, даже после следующих правок. Идентификатор с другим содержимым даёт `409`. Подтверждения действуют семь дней. Устаревшая версия также даёт `409`; клиент сохраняет форму на экране и требует обновить общую базу.

`state.recipes` обязателен и должен быть массивом. Переданные `requisitions`, `stock`, `plans`, `batches`, `stopList`, `stats`, `readNotices` также проверяются как массивы. Неизвестные поля сохраняются. Из `settings` удаляются старые `supabaseUrl`, `supabaseKey`, `workspaceId`. Запись ограничена 100 МиБ по умолчанию; настройка, вход, выход и пароли — 16 КиБ. Перед разбором большой записи проверяются сессия и CSRF; внутри транзакции они проверяются повторно.

Пароли ролей различаются; длина — минимум 12 символов, максимум 1024 байта. Пароли хранятся как scrypt-хеши. Настройка/вход ограничены 20 попытками за 15 минут на адрес соединения. За обратным прокси несколько пользователей могут делить один такой адрес; это учитывается при проверке рабочей среды.
